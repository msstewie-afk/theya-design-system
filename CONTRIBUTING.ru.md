# Как менять Theya

Как менять саму Theya: добавить компонент, исправить его, поменять токен. Как подключить Theya в приложение — в [GETTING-STARTED.ru.md](GETTING-STARTED.ru.md).

## Подготовка

```bash
pnpm install
pnpm build:tokens
git config core.hooksPath .githooks   # проверки на каждый коммит

cd packages/theya-shadcn
pnpm storybook                        # http://localhost:6008
```

Node 22, pnpm 11. После любого изменения в `packages/tokens/src` снова запустите `pnpm build:tokens`.

## Где что лежит

| Путь | Что |
|---|---|
| `packages/tokens/src/primitive` | палитра и шкалы: единственное место с сырыми значениями |
| `packages/tokens/src/semantic` | семантические токены (`color.default.json`, `color.dark.json`, размеры…): ссылки на примитивы |
| `packages/tokens/src/profiles`, `src/density` | продуктовые темы ([PROFILES.ru.md](PROFILES.ru.md)), режимы плотности ([DENSITY.ru.md](DENSITY.ru.md)) |
| `packages/theya-shadcn/src/components/ui` | компоненты: `<name>.tsx`, `<name>.stories.tsx`, `<name>.guidelines.tsx` |
| `packages/theya-shadcn/src/components/blocks` | паттерны страниц, те же три файла |
| `packages/theya-shadcn/src/lib` | вспомогательное и словари (`locale-*.ts`) |
| `packages/theya-shadcn/spec`, `api`, `public/llms*.txt` | **генерируются**, руками не правятся |
| `packages/theya-shadcn/a11y/manual.json` | ручная часть матрицы доступности: проверки со скринридером, принятые отступления |

## Компонент — это три файла

1. **`<name>.tsx`** — сам компонент.
   - `'use client'` в начале, если есть состояние, эффекты или обработчики событий (`pnpm api:check` это проверяет).
   - Цвета, размеры, радиусы, тени — только из токенов: `bg-[var(--color-…)]`, `p-[var(--size-…)]` или шкала отступов Tailwind. Без hex: проверка не пропустит (осознанное исключение — `gate-allow-hex` на той же строке, с причиной).
   - Логические стороны: `ms/me`, `ps/pe`, `start/end`, `text-start` — не `ml/mr`, `left/right` (`check-rtl.mjs` на них падает; `--fix` переводит сам).
   - Встроенный текст (подписи для скринридера, плейсхолдеры, объявления) — из словаря, не вписан в код ([LOCALIZATION.ru.md](LOCALIZATION.ru.md)).
   - Имена пропсов из общего словаря: `appearance`, `tone`, `size`, `widthSize`… — сначала посмотрите на похожий компонент.
2. **`<name>.guidelines.tsx`** — содержимое страницы Docs: статус, когда использовать, что взять вместо, анатомия, заметки о доступности, пары do / don't. У паттернов пар do / don't нет.
3. **`<name>.stories.tsx`** — `tags: ['autodocs']`, `parameters.guidelines` и сторис на каждый вариант и состояние. У интерактивных компонентов — play-тест на клавиатурный путь (Tab, стрелки, Enter, Escape) и управление фокусом.

После добавления или переименования сторис запустите **`pnpm api`**: спецификация и матрица доступности собираются из сторис.

## Правила дизайна

Те, что встречаются чаще всего:

- **Сетка 4px** для отступов и размеров. 2px допустим как полшага (заголовок → описание, соседние кнопки в тулбаре).
- **Внешний отступ больше внутреннего**: в кнопке боковой отступ всегда больше расстояния между иконкой и текстом; в поповере расстояние между полями меньше его отступа.
- **Иконка и текст:** 4px рядом с иконкой 12px или мелким текстом, 8px рядом с иконкой от 16px.
- **Отступы в полях:** 12px у полей 32 и 40px, 16px у полей 48px.
- **Разделители** внутри карточек, диалогов и панелей отступают на ширину отступа контента; разделители строк в таблицах и списках — от края до края.
- **Бордеры:** `border` — поля и контролы, `border-subtle` — карточки и таблицы, `border-subtler` — разделители и строки.
- **Ссылки в тексте** подчёркнуты или на одну ступень жирнее окружающего текста.
- **Текущий пункт** (навигация, разделы) отмечен не только цветом: полужирная подпись и полоса 2px у начального края.
- **Меньше 5 вариантов** — радиокнопки, а не Select.
- **Текст в полях на телефонах — 16px**, чтобы iOS не увеличивал страницу при фокусе.
- **Тексты** — по [WRITING.ru.md](WRITING.ru.md).

## Доступность

Цель — WCAG 2.2 AA, в светлой и тёмной теме.

- Каждая сторис проходит axe в обеих темах в CI; нарушение валит сборку. Локально: `pnpm test-storybook <file>` и `pnpm test-storybook:dark <file>`.
- Правило, выключенное для сторис, требует причины в комментарии рядом; оно попадает в матрицу.
- Контраст: 4.5:1 для текста, 3:1 для иконок, бордеров контролов, focus ring и статусных точек — и в тёмной теме.
- Цели не меньше 24×24px; движение — за `motion-safe:` / `motion-reduce:`; стили `forced-colors` там, где состояние показано только цветом или фоном.
- Проверки со скринридером вносятся в `a11y/manual.json` вручную.

## Токены

- Новый цвет — семантический токен со ссылкой на примитив (`{color.blue.blue-500}`), со значением и в `color.default.json`, и в `color.dark.json`. А не примитив прямо в компоненте.
- Прежде чем добавить токен, поищите подходящий: Storybook → Design System / Foundations.
- Переименование или удаление токена — ломающее изменение: changeset с таблицей переименований.
- Переменные в Figma синхронизируются из того же источника ([TOKENS-EXPORT.ru.md](TOKENS-EXPORT.ru.md)).

## Перед коммитом

Проверка на коммит смотрит типы, hex-цвета в компонентах и что `spec/` и `llms*.txt` не устарели. Тестов она не заменяет:

- [ ] `pnpm exec tsc --noEmit -p .`
- [ ] `pnpm api` после изменения сторис, пропсов или правил; `pnpm api:check` проходит
- [ ] play + axe для изменённых сторис, светлая и тёмная тема
- [ ] взгляд в Storybook в обеих темах, и на ширине телефона
- [ ] changeset на всё, что заметит приложение: `pnpm changeset` ([RELEASING.ru.md](RELEASING.ru.md)); для одних сторис, тестов и документации не нужен. Ожидающие changesets видны на странице Design System / Changelog в Storybook
- [ ] руководства на двух языках: у каждого `X.md` в корне есть пара `X.ru.md`

Никогда не используйте `--no-verify`. Если проверка ошибается, исправьте проверку.

## Pull request

CI проверяет типы, `api:check`, сборку песочницы, play + axe и визуальную регрессию в обеих темах, React 19 и продуктовые темы ([TESTING.ru.md](TESTING.ru.md#ci-github-actions)). Pull request падает на визуальном изменении: посмотрите архив `visual-diffs` и, если изменение задумано, напишите об этом в описании.
