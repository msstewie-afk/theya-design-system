# a11y-kit

Проверки доступности для дизайн-системы и продуктов на ней — из одного реестра: каждая проверка каждого слоя (код, компоненты в Storybook, страницы продукта, агент-ревьюер, люди), критерии WCAG 2.2, которые она подтверждает, её глубина и на чём она откалибрована.

English: [README.md](./README.md).

**Состояние (19.11.2026): шаг 1 плана — реестр.** Скрипты Theya (`a11y-tree`, `a11y-auto`, `a11y-states`, `a11y-forced`, матрица) пока в `packages/theya-shadcn/scripts`, сюда переезжают на шаге 3.

## Принцип: ничего на веру

Вердикт выносит детерминированный скрипт, а не модель: одинаковый вход — одинаковый JSON. Каждая проверка откалибрована на известных дефектах и чистых примерах (калибровочные сториз ДС, тест-кейсы W3C ACT, одно известное нарушение на правило axe), и калибровку человек запускает в своём терминале. Выборка находок каждого прогона уходит человеку, он отмечает «подтверждено» или «ложное», и точность каждой проверки видна в отчёте. Единственный слой с моделью — ревью PR — помечен как мнение и сборку не роняет.

## Команды

Из пакета дизайн-системы (там, где `a11y-kit.config.mjs`):

```bash
node ../a11y-kit/bin/a11y-kit.mjs registry          # реестр и список проверок (EN + RU)
node ../a11y-kit/bin/a11y-kit.mjs registry --check  # ошибка, если устарели (в Theya: pnpm api:check)
node ../a11y-kit/bin/a11y-kit.mjs compare list.json # чек-лист другой команды против реестра
node ../a11y-kit/bin/a11y-kit.mjs calibrate-axe     # одно известное нарушение на правило axe, как axe запускается в CI (конфиг `axe`)
```

`compare` принимает `[{ "id": "1.4.3-color-contrast", "sc": ["1.4.3"], "where": "ds" }, …]` (префикс критерия и `sc` необязательны; правило axe узнаётся по id после префикса) и показывает: строки, которые не правило axe и не проверка реестра (и что в реестре есть по их критерию); правила axe, которые запускаются только при явном включении (экспериментальные, устаревшие, выключенные); критерии, которые строка теряет, хотя axe связывает правило с ними; критерии WCAG 2.2 A/AA без строки; проверки реестра, для которых в списке нет строки.

## План

1. Реестр, список проверок, сравнение с другими чек-листами. **Сделано.**
2. Калибровка axe: одно известное нарушение на правило, прогон как в CI (теги, порог impact, корень сканирования) → поймано / ниже порога / только на проверку / не поймано / не запускается / уровень страницы, в реестр. **Сделано** (`a11y-kit calibrate-axe`).
3. Движок: tree, auto, states, forced переезжают сюда за адаптером ДС (сториз → компонент, папки кода, темы); вывод Theya должен остаться тем же.
4. Чтение кода (2.1.4, 2.3.1, 2.5.1, 2.5.2, 2.5.7, 3.3.8), покрытие того, что прогон отрисовал (компоненты, ошибка, загрузка, disabled, expanded), режим страниц для продуктов (URL, проверки уровня страницы, находки привязаны к компонентам ДС через `data-slot`), выборка на ручную проверку (точность каждой проверки), промпт ревью PR из реестра и глубина, которой нет в списках: 2.2.1 таймауты, 2.2.2 пауза, 1.3.5 отсутствующий `autocomplete`, 1.4.1 состояние только цветом, 3.3.2 инструкции, пиксельная видимость фокуса в обычном режиме, неконтентный контраст, контраст текста там, где axe не может сказать.
